# Traject AI 启发式判断规则

本文档定义 AI 在初始化扫描阶段判断目录/文件是否应排除的规则。
规则分为硬规则（确定性自动排除）和软规则（AI 判断，标注置信度）。

## 一、判断原则

AI 的核心判断原则：**只索引有意义的代码实现文件**。以下内容不应纳入索引：

1. 构建产物和缓存（编译输出、临时文件）
2. 第三方依赖（通过包管理器安装的代码）
3. 平台胶水代码（Xcode 项目文件、Android 项目模板、平台通道代码）
4. 自动生成的代码（代码生成器产出，非手写）
5. 纯资源文件（图片、字体、音频、视频）
6. 国际化资源文件（`.arb`、`.strings`、`.po` 等翻译文件）

## 二、目录级硬规则（自动排除，无需用户确认）

以下条件满足任一即自动排除：

### 2.1 目录名精确匹配

```
Pods/           ephemeral/      .symlinks/      .plugin_symlinks/
.xcodeproj/     .xcworkspace/   Assets.xcassets/  Base.lproj/
Configs/        Flutter/        .dart_tool/      .git/
.svn/           .hg/            node_modules/    __pycache__/
```

### 2.2 目录名模式匹配

```
*.framework/        # macOS/iOS framework bundles
*.xcworkspace/      # Xcode workspace
*.xcodeproj/        # Xcode project
*.app/              # 编译后的应用包
*.bundle/           # 资源 bundle
```

### 2.3 目录不在 git 跟踪中

如果目录满足以下所有条件，自动排除：

1. 目录名匹配以下模式之一：`generated/`、`auto_gen/`、`__*__/`、`cache/`、`temp/`、`tmp/`、`output/`、`out/`、`build/`
2. `git ls-files` 在该目录下无任何被跟踪文件
3. 目录非空

### 2.4 特殊平台目录

```
linux/              # Flutter Linux 平台目录（自动生成）
elinux/             # Flutter Embedded Linux 平台目录
web/                 # Flutter Web 平台目录（自动生成）
windows/            # Flutter Windows 平台目录（判断：若目录下无手写 .cpp/.h 文件，则为自动生成）
macos/              # Flutter macOS 平台目录（判断：若 Runner/ 占主导，则为自动生成）
android/            # Flutter Android 平台目录（判断：若 app/ 下全是 Gradle 模板，则为自动生成）
ios/                # Flutter iOS 平台目录（判断逻辑同 macos/）
```

## 三、目录级软规则（AI 判断，标注置信度）

### 3.1 高置信度排除（置信度 ≥ 80%）

触发条件（满足任一即可）：

| 条件 | 检测方法 |
|------|---------|
| 目录下源码文件占比 < 10% | 统计目录内文件扩展名，源码扩展名见 conventions.md 第六节 |
| 目录下所有文件都是锁文件/配置文件/资源文件 | 对每个文件分类，全部非源码即触发 |
| 目录名强烈暗示为生成产物 | `generated/`、`auto_gen/`、`gen/`、`__generated__/` |
| 目录下所有文件头部都包含 `@generated` 或 `auto-generated` 标记 | 抽样检查 3-5 个文件的前 20 行 |

### 3.2 中置信度排除（置信度 50%-79%）

触发条件（满足任一即可）：

| 条件 | 检测方法 |
|------|---------|
| 目录下源码文件占比 10%-30% | 统计扩展名分布 |
| 目录名暗示为工具/辅助性质 | `scripts/`、`tools/`、`fixtures/`、`mocks/`、`stubs/`、`examples/`、`samples/` |
| 目录下主要是配置文件（`.yaml`、`.json`、`.xml`、`.plist`）和少量源码 | 配置文件 > 70% |
| 目录在 `.gitignore` 中被整体忽略 | 检查 `.gitignore` 规则 |

### 3.3 低置信度（保留索引，仅提示）

触发条件（满足任一即可）：

| 条件 | 检测方法 |
|------|---------|
| 目录下源码文件占比 30%-50% | 混合目录，可能是工具目录含部分源码 |
| 目录名不够明确 | `misc/`、`utils/`、`helpers/`、`common/`（可能包含核心工具代码） |
| 目录是空目录 | 标记为「空目录」 |

## 四、文件级硬规则（自动跳过）

以下文件在索引时自动跳过，不列入 `.traject.md` 的「文件」表格：

### 4.1 二进制文件（扩展名匹配）

```
.png, .jpg, .jpeg, .gif, .ico, .svg, .webp, .bmp
.woff, .woff2, .ttf, .otf, .eot
.mp3, .mp4, .wav, .avi, .mov, .webm
.pdf, .doc, .docx, .xls, .xlsx, .ppt, .pptx
.zip, .tar, .gz, .bz2, .7z, .rar
.o, .a, .so, .dylib, .dll, .exe, .lib
.keystore, .jks, .p12, .cer, .pem（非代码类证书文件）
```

### 4.2 自动生成文件（文件名模式匹配）

```

*.freezed.dart      # Freezed 生成代码
*.gr.dart           # GRPC 生成代码

```

## 五、文件级软规则（AI 判断）

对于不匹配硬规则的文件，AI 读取文件头部（前 20 行）进行判断：

### 5.1 判定为自动生成（跳过索引）

| 检测标记 | 置信度 |
|---------|--------|
| 文件头部包含 `@generated` 注释 | 高 |
| 文件头部包含 `auto-generated` / `AUTO-GENERATED` | 高 |
| 文件头部包含 `DO NOT EDIT` / `DO NOT MODIFY` 标记 | 高 |
| 文件头部包含 `This file was automatically generated by` | 高 |
| 文件头部包含代码生成器名称（`generated by`、`Created by` + 工具名） | 中 |

### 5.2 判定为配置文件（索引但标注为「配置」）

| 检测条件 | 标注 |
|---------|------|
| 文件内容主要是键值对配置 | 职责标注为「配置」 |
| 文件是 CI/CD 配置（`.github/workflows/`、`Makefile`、`Dockerfile`） | 职责标注为「CI/CD」 |

## 六、AI 判断执行流程

在初始化步骤 1.2（扫描阶段），AI 按以下顺序执行：

```
1. 加载 Profile 规则（common.yaml + 检测到的平台 profile）
   → 得到确定性的排除列表

2. 扫描项目根目录，列出所有一级目录

3. 对每个非 Profile 排除的一级目录：
   a. 检查目录级硬规则（第 2 节）
      → 匹配 → 自动排除
   b. 检查目录级软规则（第 3 节）
      → 匹配 → 按置信度分级
   c. 均不匹配 → 保留索引

4. 汇总结果，按置信度分组展示给用户确认
```

## 七、与 Profile 规则的优先级

```
Profile 排除规则  >  AI 硬规则  >  AI 软规则（高置信度）  >  AI 软规则（中置信度）  >  默认保留
```

- Profile 规则是用户可知可控的确定性规则，优先级最高
- AI 硬规则次之（基于明确模式匹配，确定性高）
- AI 软规则用于补充覆盖，仅对 Profile 和硬规则未覆盖的目录/文件生效
- 如果 AI 认为 Profile 规则可能有问题，在确认环节提示用户，但不自动覆盖
