# Traject 格式规范

## 一、.traject.md 硬性约束

| 约束项 | 限制值 | 说明 |
|--------|--------|------|
| 最大行数 | 30 行 | 含标题、空行、表格。超过 30 行视为无效索引 |
| 文件描述长度 | ≤ 10 字（中文）/ ≤ 20 字符（英文） | 「职责」列，简洁命名 |
| 子目录描述长度 | ≤ 20 字 | 「子目录」表格中的职责列 |
| 职责行长度 | ≤ 20 字 | `## 职责` 段落，一句话概括 |
| 关键符号数 | ≤ 3 个/文件 | 函数名、类名、导出常量等 |
| 内容范围 | 仅直接子级 | 禁止跨级引用孙子目录或文件 |

## 二、关键符号定义

「关键符号」指文件中对外暴露的主要接口，包括：
- **函数/方法**：导出或公共函数名
- **类/结构体**：类名、接口名、结构体名
- **常量/变量**：导出的常量或全局变量
- **组件名**：React/Vue 组件名

优先级：导出符号 > 公共方法 > 核心内部函数

## 三、.traject.md 必填字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `# 目录索引` | ✅ | 标题，格式：`# 目录索引: [相对路径]` |
| `## 职责` | ✅ | 一句话概括目录功能 |
| `## 子目录` | 条件必填 | 有子目录时必须填写，无子目录可省略 |
| `## 文件` | 条件必填 | 有文件时必须填写，无文件可省略 |
| `## 依赖` | 可选 | 依赖的其他目录，无依赖可省略 |

## 四、拓扑排序规则

生成索引时，目录按以下规则排序：

1. **深度优先**：depth 越大越先生成（叶子节点优先）
2. **同深度字母序**：同 depth 目录按完整路径字母序排列
3. **确定性**：相同输入必须产生相同顺序

```
示例：
depth=3: src/components/buttons/  → 第 1 批
depth=3: src/components/forms/    → 第 1 批
depth=2: src/components/          → 第 2 批（等子节点完成）
depth=2: src/utils/               → 第 2 批
depth=1: src/                      → 第 3 批
depth=0: ./                        → 最后（manifest.md）
```

## 五、自下而上生成原则

### 数据流

```
叶子目录         → 读取源码文件     → 生成 .traject.md
非叶子目录       → 读取子级 .traject.md → 生成 .traject.md
根目录           → 读取一级 .traject.md → 生成 manifest.md
```

### 禁止行为

- ❌ 父目录读取孙子目录的 `.traject.md`（跨级汇总）
- ❌ 父目录直接读取源码文件（应从子级索引获取信息）
- ❌ 一次性读取所有 `.traject.md`（应逐级深入）
- ❌ 在子目录未完成前生成父目录索引

### 内容来源矩阵

| 生成目标 | 「职责」来源 | 「子目录」来源 | 「文件」来源 |
|----------|-------------|---------------|-------------|
| 叶子 .traject.md | 分析源码文件 | 无（叶子） | 直接读取源码文件 |
| 父级 .traject.md | 汇总子级职责 | 读取子级 .traject.md 的职责行 | 读取本目录直接文件 |
| manifest.md | 汇总一级职责 | 读取一级 .traject.md 的职责行 | 不涉及 |

## 六、文件分类规则

### 需要索引的文件类型

| 类型 | 扩展名示例 | 提取方式 |
|------|-----------|---------|
| 源码 | `.ts`, `.js`, `.py`, `.go`, `.rs`, `.java`, `.kt`, `.swift`, `.dart`, `.c`, `.cpp`, `.h`, `.hpp` | 读文件提取符号 |
| 配置 | `.json`, `.yaml`, `.toml`, `.env.example` | 标注为配置文件 |
| 文档 | `.md`, `.rst`, `.txt` | 标注为文档 |
| 样式 | `.css`, `.scss`, `.less` | 标注为样式 |
| 模板 | `.html`, `.vue`, `.jsx`, `.tsx`, `.svelte` | 读文件提取组件名 |

### 跳过的文件类型

| 类型 | 原因 | 检测方式 |
|------|------|---------|
| 二进制文件 | 无法提取文本信息 | 扩展名匹配 + `file` 命令，详见 `heuristics.md` 第 4.1 节 |
| 图片/视频/音频 | 非代码文件 | 扩展名匹配 |
| lock 文件 | 依赖锁定文件，不反映源码 | 在 Profile `exclude_files` 中 |
| 自动生成的文件 | 不反映源码意图 | 文件名模式匹配 + 文件头部标记检测，详见 `heuristics.md` 第 4.2 节和第 5 节 |

### 文件级 AI 判断

对于不匹配硬规则的文件，执行以下判断（详见 `heuristics.md` 第 5 节）：

1. 读取文件头部（前 20 行）
2. 检查自动生成标记：`@generated`、`auto-generated`、`DO NOT EDIT`、`This file was automatically generated by`
3. 命中标记 → 跳过索引
4. 未命中 → 正常索引，提取关键符号和职责

## 七、行数计算规则

`.traject.md` 的行数计算：
- 标题行（`#`）计入
- 空行计入
- 表格行（`|---|`）计入
- 模板中的注释不计入

30 行分配建议：
```
# 目录索引: path          (1 行)
                          (1 空行)
## 职责                   (1 行)
职责描述                  (1 行)
                          (1 空行)
## 子目录                 (1 行)
| 目录名 | 职责 |         (1 行)
|--------|------|         (1 行)
| dir1/  | ...  |         (最多 10 行)
                          (1 空行)
## 文件                   (1 行)
| 文件名 | 职责 | 符号 |  (1 行)
|--------|------|------|  (1 行)
| file1  | ...  | ...  |  (最多 7 行)
                          (1 空行)
## 依赖                   (1 行)
依赖描述                  (1 行)
─────────────────────────
总计：最多 30 行
```

## 九、排除配置规范

### Profile 分层结构

排除配置按项目类型分层管理，位于 `references/excludes/` 目录：

| Profile 文件 | 适用场景 | 检测标志 |
|-------------|---------|---------|
| `common.yaml` | 所有项目 | 始终加载 |
| `flutter.yaml` | Flutter / Dart 项目 | `pubspec.yaml` |
| `node.yaml`（未来） | Node.js / 前端项目 | `package.json` |

### 合并规则

1. 初始化时扫描项目根目录的标志文件
2. 加载 `common.yaml` + 所有匹配的平台 Profile
3. 多个 Profile 中的同名字段合并（数组去重）
4. 合并后的完整配置写入项目 `.traject/exclude.yaml`

### 排除字段语义

| 字段 | 匹配方式 | 示例 |
|------|---------|------|
| `exclude_dirs` | 目录名匹配（任意层级） | `node_modules/` 匹配所有层级下的 `node_modules` |
| `exclude_paths` | 路径模式匹配（从项目根开始） | `example/macos/Runner/` 只匹配该特定路径 |
| `exclude_files` | 文件名或 glob 模式 | `*.g.dart` 匹配所有 `.g.dart` 文件 |

### 用户自定义

用户可以在 `.traject/exclude.yaml` 中手动增删排除项：
- `user_additions`：用户额外添加的排除项
- `user_removals`：用户从 Profile 中移除的排除项
- 下次 `Traject 更新` 时，增量合并用户自定义 + Profile 规则

## 八、描述语言规范

- 职责描述使用**动词短语**或**名词短语**，禁止完整句子
- 中文项目使用中文描述，英文项目使用英文描述
- 关键符号保持原始代码中的名称（不翻译）
- 描述应当**具体**，避免「工具函数」「通用组件」等模糊表述
